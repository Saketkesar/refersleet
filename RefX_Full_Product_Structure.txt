REFX — FULL PRODUCT, REPOSITORY, WEBSITE & API SPECIFICATION
================================================================

Project Name: RefX
Tagline: Community-powered referral programs for India
Repository model: Open source + GitHub Pull Requests
Primary data source: GitHub repository
Website: RefX web application
API: Free public API
Country focus: India
License recommendation: MIT for code; referral data should have a clearly documented data license.

================================================================
1. PRODUCT VISION
================================================================

RefX is a community-powered directory of active referral programs, invite
offers, rewards, freebies, student offers, SaaS credits and similar programs
available to users in India.

The project has three connected products:

1. Open-source GitHub repository
   - Community contributes referral records.
   - Contributions are submitted through Markdown files.
   - Pull Requests are reviewed by maintainers.
   - GitHub is the transparent source of truth.

2. RefX website
   - Search and browse referral programs.
   - Show rewards, eligibility, screenshots, terms and verification status.
   - Give contributors public credit.
   - Allow non-technical users to submit through a web form.
   - Allow the community to verify or report referral programs.
   - RefX owns and displays the platform referral/redirect URL.

3. Free public API
   - Exposes structured referral data.
   - Developers can build bots, browser extensions, apps and other services.
   - API documentation and OpenAPI specification are public.

CORE PRINCIPLE:
The community supplies and verifies information.
RefX moderates, structures, publishes and operates the referral links.

4. REFERRAL DATA FORMAT
================================================================

Each referral should be predictable and machine-readable.

Recommended file:

referrals/finance/payments/example.md

Example structure:

---
id: example-company
name: Example Company
slug: example-company

status: active

category:
  - finance
  - payments

subcategories:
  - upi
  - cashback

country:
  - IN

official_website: https://example.com

reward:
  referrer: "₹500"
  referred_user: "₹500"
  type: cashback
  description: "Reward after completing eligible activity."

eligibility:
  - Indian users
  - New users only

requirements:
  - Account creation
  - KYC
  - Eligible transaction

terms_url: https://example.com/terms

submitted_by:
  username: github-user
  display_name: Example User

submitted_at: 2026-08-23

last_verified: 2026-08-23

verification:
  status: community-verified
  working_votes: 0
  not_working_votes: 0
  reward_changed_votes: 0

tags:
  - cashback
  - new-user
  - student

screenshots:
  - https://example.com/screenshot.png

description: |
  Full explanation of the referral program.

notes: |
  Additional community notes.

refx:
  redirect_slug: example-company
  disclosure_required: true

---

IMPORTANT:
The contributor's raw referral URL should NOT become the permanent public
source URL in the repository if RefX is operating the referral link.

Instead, the internal/admin system stores the actual destination securely,
while the public-facing website uses:

https://refx.example/r/example-company

This lets RefX control the outbound referral URL and tracking.

10. COMMUNITY VERIFICATION
================================================================

Every published referral can receive community feedback.

Actions:

WORKING
NOT WORKING
REWARD CHANGED
ELIGIBILITY CHANGED
PROGRAM ENDED
WRONG INFORMATION

Verification should not simply count raw votes.

Suggested confidence model:

Base score
+ recent confirmations
+ trusted contributor confirmations
+ administrator verification
- failed reports
- age decay
- suspicious activity


STATUS LEVELS:

95–100:
Highly Verified

85–94:
Verified

70–84:
Mostly Verified

50–69:
Needs Verification

Below 50:
Questionable


Automatic stale state:

If no verification activity for 90 days:
"Needs verification"

If no verification activity for 180 days:
"Stale"

30. DATA SOURCE RULE
================================================================

GitHub is the canonical community data source.

Database is an operational/indexing layer.

Website reads the normalized data.

API reads the normalized data.

This avoids having:

GitHub data != Website data != API data.

There should be one ingestion pipeline.

36. WEBSITE SUBMISSION RULE
================================================================

The web submission form is NOT an alternative moderation system.

It is an easier frontend for creating the same GitHub contribution.

Goal:

Non-technical user:

41. GOLDEN RULES
================================================================

1. GitHub remains the transparent source of truth.
2. Every referral must have structured data.
3. Every contributor gets visible credit.
4. RefX controls the public referral URL.
5. Community verification affects trust, not truth by itself.
6. Admins can override malicious or clearly false information.
7. All moderation should be auditable.
8. Website submissions should eventually become GitHub PRs.
9. API data should match website data.
10. Never fabricate referral programs.
11. Clearly disclose referral/affiliate monetization.
